## THL-26: the CI to CD flow on the dashboard

**Asked:** "can you tell me if the end to end ci cd pipeline built and automated?", then "so for
this project do we have lower and prod separate env? explain the ci to cd flow", then "add the CI
to CD flow to the dashboard".

**The answer first:**
- **CI is built and automated.** Five checks run on every pull request and on `main`, and the
  ruleset requires all five by name.
- **CD is not built, by design.** There is no service to ship until Phases 1–6 build one.
  Phase 7 builds Kaval's pipeline on Azure: build once, staging on demand, promotion by digest.
  Kaval already runs `release.yml`, `promote.yml` and `rollback.yml`.
- **There are no lower and prod environments yet.** The only infrastructure is the guardrails'
  resource group. local, staging and prod are designed (ADR-0002) and arrive in Phase 7.
- **Cost:** inside the ₹1,500 ceiling nothing runs all month, prod included. Prod will be started
  for demos and drills and then parked.

**Built (`architecture.toml` and the DevOps view):**
- **The graph's Phase 7 column** is now the CD path: build once, staging, the promote gate (new),
  production.
- **Two sequences:**
  - *From a merge on main to production* (13 steps): `release.yml`'s two jobs with split powers,
    the staging pull request, Flux pulling by digest, the smoke test and the passed-staging
    record, `promote.yml`'s read-only gate, and the prod pull request whose merge is the
    go / no-go.
  - *Rolling production back* (6 steps), which stops if going back would cross a database
    migration.
- **The environments table:** local, staging and prod, with where each runs, when and what it
  gets. Each state follows Phase 7 in ROADMAP.md.
- **"Kaval's pipeline, moved to Azure":** ECR becomes Container Registry, the IAM role becomes an
  Entra ID federated credential, Parameter Store becomes Key Vault. Helm, Flux, cosign, the SBOM
  and the promotion guard stay as they are.
- **Eight glossary terms:** GitOps, Flux, Helm chart, image signature, workload identity
  federation, passed-staging record, promotion guard, rollback.
- **Labelled honestly:** the file says this is the shape Phase 7 builds to, and Phase 7's spec
  fixes the details.

**Found in the browser, fixed:**
- A five-lane sequence stretched to the card's width, so its text came out 1.7 times larger than
  a seven-lane one. Sequences are now capped at 1.25 times their natural width and centred. This
  also helps the narrow flows on the Flows view.
- A link to a section heading landed under the sticky tab bar. Headings and table rows with an id
  now get the same scroll margin as cards.
- JetBrains Mono turned `-<` in `sha-<short>` into an arrow. Code now shows no ligatures, so every
  character reads as typed.

**Measured:**
- Time: about 1 hour of one session.
- Pages reviewed by Roshan: the page itself.
- Defects caught before merge: 4. Three are listed above; the fourth was an f-string nesting the
  same quote character, which Python 3.12 accepts but CI's Python 3.11 rejects.
- Tests: 283 pass, with the two architecture tests extended to the CD flows, the environments and
  the Kaval table.
- Tokens: not measured.

### THL-29: Postgres in compose, the same image in CI (SPEC-002 Task 2, R1)

**Built:**
- **`compose.yaml`:** one service, Postgres with pgvector.
  - The image is pinned by digest, the same one Kaval pins.
  - The port is published on 127.0.0.1 only.
  - The credentials come from `.env` and must be set (`${VAR:?...}`).
  - Nothing is built here, and the data lives in a named volume.
- **CI's `test` job** runs the same image, by digest, as a service with throwaway credentials. A
  test ties the two digests together, so they cannot drift.
- **`make db-up` / `make db-down`.**
- **`.env.example`** now names the database and user `thalam`.

**The code review found:**
- **A healthcheck that could pass too early.** `pg_isready` without `-h` checks the Unix socket.
  On a fresh volume, the image's entrypoint first runs a temporary server on the socket only, then
  restarts it. So "healthy" could come before TCP was up, and Task 3's first connection would have
  failed once. Both healthchecks now check `-h 127.0.0.1`.
- **A blind spot in the test.** It now also refuses `network_mode`, because host networking would
  bypass the 127.0.0.1 binding.
- **For Lab 01:**
  - `make db-down` also needs `.env`, because Compose checks every variable on every command.
  - `restart: unless-stopped` brings Postgres back each time Docker starts, until `make db-down`.

**Found on the laptop, not in the repo:** a `$` inside a Phase 0 password in `.env`. Compose
expands `$` in `.env` values, so every Compose command warned about an unset variable. Roshan
wrapped that value in single quotes. Compose leaves single-quoted values alone, and both repo
parsers strip the quotes.

**Process slip:** a reviewer's repo-wide `grep -r` matched two non-secret `.env` lines, the old
database and user names. Agent briefs now say to search with the Grep tool, which skips
git-ignored files, or to pass `--exclude='.env*'`.

**Measured:** about 0.5 hours. Defects: 1 minor (the healthcheck) and 1 test gap, both fixed before
merge. Tests: 305 (299 + 6). Tokens: not measured.
