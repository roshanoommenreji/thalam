### THL-30: the release-graph schema and the database test guard (SPEC-002 Task 3, R2, R14)

**Built:**
- **`thalam_shared.lifecycle`:** the nine release states and the moves allowed between them.
- **`thalam_shared.db`:** one SQLAlchemy engine per role (owner, loader, reader). Each is built
  from settings by name, with a 5 s connect timeout. The URL is never printed.
- **`thalam_shared.models` and migration `0001`:** the seven tables. The CHECKs put the life
  cycle's shape into the database, and no foreign key cascades, so "retire, never delete" is
  enforced by Postgres, not by habit.
- **`services/conftest.py`:** a test that needs Postgres asks for `db`. It gets one transaction,
  rolled back at the end, and starts from empty tables. Without a reachable database at the
  migration head, the test skips and says why. CI sets `THALAM_REQUIRE_DB=1`, which turns that
  skip into a failure, so a database test cannot quietly vanish from a green run (Kaval KAV-24).
- **CI** migrates up, runs `alembic check`, migrates down and up again, then runs the tests.
- **`make migrate`.**

**The code review found:**
- **CHECK constraints were never compared.** `alembic check` and Alembic's `compare_metadata`
  ignore CHECKs, and server defaults too unless asked. The state list is written twice, in
  `lifecycle.STATES` and in the migration, as a migration must not import app code. A state
  added to one copy only would have passed every test. A new test builds the models in a
  throwaway schema and compares every CHECK with the migrated one. Adding `'paused'` to
  `STATES` alone now fails it. `compare_server_default` is on.
- **SQLAlchemy errors print the values bound into a query.** Task 4 binds the role passwords that
  way, and Task 8 binds untrusted text. The engines now use `hide_parameters=True`, and a test
  proves a bound value stays out of the error.
- **`localhost` costs 5 s per connection on Windows, even when Postgres is up.** `localhost`
  tries `::1` first, Postgres listens on `127.0.0.1` only, and psycopg waits the whole connect
  timeout before trying the next address. Measured: 5.08 s against 0.06 s. `.env.example` and CI
  now say `127.0.0.1`.
- **The probe counted any database with an `alembic_version` table as migrated.** That
  includes one after `alembic downgrade base`, and one behind a later migration. It now compares
  the version with the head.
- **`release_event` was unique on `(release_id, kind, at)`.** Task 7 requires each event to be
  later than the one before, whatever its kind, so the key is now `(release_id, at)`.

**The plan was wrong in three places:**
- Step 9 expected 3 skips without a database. There are 2, now 4 with the new tests, because the
  reversibility test only reads files.
- It listed `.env.example` with no step for it.
- Task 12's Lab 01 settings say `localhost`. Lab 01 will say `127.0.0.1`.

**Construction note:** after the laptop restarted, Docker Desktop was down and so was the
throwaway database `thalam-construct`. Restarting the container kept its data.

**Open (deferred from the review):**
- `migrations/env.py` prints the host when Postgres is unreachable. Fix it before any
  non-local database, at the latest in Phase 7 (rule 6).
- `@lru_cache` on `engine` hides the `Role` type from mypy.
- `lifecycle`'s next-state map depends on positions in the `STATES` tuple.
- `migrations/` is outside mypy.
- Name new migrations with `alembic revision --rev-id 0002`.

**Measured:** about 1 hour of agent time across two sessions. Defects: 3 important and 3 minor,
all fixed before merge. Tests: 312 (305 + 7). Subagent tokens: about 0.6 M (implementer, spec
review, code review and re-review).

### THL-31: a reader and a loader that cannot change history (SPEC-002 Task 4, R3)

**Built:** Kaval's agent/executor split, one layer down, in Postgres (CLAUDE.md rule 3).
- **`thalam_reader`** may only read. `make ask` uses it, and Phase 2's agent will inherit it.
- **`thalam_loader`** keeps the mirror tables in step with the files. It may only INSERT into the
  written-once tables: `release`, `release_need` and `release_event`.
- **`make db-roles`** runs `scripts/ops/db-roles.sql` as the owner after every `make migrate`. It
  is safe to repeat, and CI runs it before the tests.
- **Tests:** `as_role` applies the real script inside the test's rolled-back transaction, then
  switches role. Every refusal must be SQLSTATE 42501, so a NOT NULL or foreign-key error cannot
  pass as "refused".

**The code review found:**
- **A password on the error path.** When a statement inside the roles script's `DO` block fails,
  PL/pgSQL quotes the statement in the error's CONTEXT line. That includes
  `ALTER ROLE ... PASSWORD '<plaintext>'`, and it reaches the server log even with statement
  logging off. The runner caught only "unreachable", so the traceback would also have printed
  it. Two runs at once would trigger it, and so would a managed server where the owner is not a
  superuser. Three fixes:
  - the runner now sends a SCRAM verifier computed on the client, as `psql \password` does, so
    the plaintext never reaches Postgres;
  - the script raises its own errors without the statement text;
  - the runner prints only the error class and SQLSTATE.
  A test runs the script as the reader, which must fail, and asserts that neither the password
  nor the verifier appears in the error.
- **The loader could rename components.** A component's identity is its name, and releases point
  at its id. Three UPDATEs swapping two names moved a release to the other component, so "cannot
  change history" was false. The loader now gets UPDATE only on the five columns Task 8 writes.
- **The reader had side doors.**
  - Large objects persist when committed.
  - It could create temp tables, send `pg_notify` and take advisory locks.
  - PUBLIC keeps CONNECT and TEMP on the database.
  The reader now logs in with `default_transaction_read_only = on`, and the database's CONNECT
  and TEMP are revoked from PUBLIC.
- **Nothing logged in as either role.** `SET ROLE` skips the login, the password and the role's
  own settings. A new test logs in as both roles for real, and it caught the read-only setting
  missing before the fix.
- **Smaller fixes:**
  - an advisory lock, so two runs queue;
  - sequence grants revoked on a re-run;
  - a check that neither role ever holds superuser, createrole, createdb, bypassrls or a
    membership;
  - TRUNCATE in the refusal tests;
  - a test that every table has a grant decision.

**The plan was wrong in two places:**
- Step 5's first failure is `ModuleNotFoundError: No module named 'db_roles'` at collection, not
  `FileNotFoundError`.
- Its test step comes after the code steps, so the test was not written first.

**Open:**
- Chain `make db-roles` into `make migrate`. A forgotten run fails safe today, with 42501.
- A `statement_timeout` for the reader.
- **Phase 7, on managed Postgres:**
  - the same principal must create the roles, run the migrations and run this script;
  - server logs go to Log Analytics, so error paths matter more there;
  - an ADR should weigh Entra ID logins for the app roles, which need no password at all;
  - on a shared cluster, the roles can still connect to the `postgres` database.
- **Phase 2:** rule 3 makes the agent's output a `proposals` row, so the agent cannot log in as
  the read-only `thalam_reader` itself. It gets its own login role that is a member of
  `thalam_reader`, with INSERT on `proposals` only. Members inherit the reader's grants and
  CONNECT, but not its `ALTER ROLE … SET` settings.
- **Task 12 (SPEC-002 amendments):** the R3 row should say "read-only at login, and PUBLIC has
  no CONNECT or TEMP". The plan's Task 4 code blocks show the code before these fixes.

**The re-review** found four small gaps, all fixed before merge:
- the leak test passed on any unrelated failure, so it now pins SQLSTATE 42501 and the role
  name;
- a statement timeout slipped past `WHEN OTHERS` and printed the verifier, never the
  plaintext;
- the runner hid Postgres's primary message, which never contains the statement;
- nothing proved the TEMP revoke.

**Measured:** about 2 hours of agent time. Defects: 3 important and 9 minor, all fixed before
merge. Tests: 329 (312 + 17). Subagent tokens: about 0.9 M.
