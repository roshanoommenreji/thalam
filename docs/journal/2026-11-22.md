## THL-23: the ceiling is ₹1,500 a month (ADR-0013)

**Azure live check:** Roshan's `az login` needed `az account clear` first, because the CLI still held the
expired August login. What it showed, read-only and with no IDs printed:
- **Subscription:** pay-as-you-go, spending limit off.
- **Billing:** a Microsoft Customer Agreement in India, billed in **INR**.
- **The AI-103 Foundry account:** 0 deployments.
- **Claude Haiku 5.5:** offered as Global Standard in East US 2 and West US 3.
- **India:** on Anthropic's supported list.

**The catch:** Azure budgets are set in the billing currency. ADR-0008's $100 and $20 came out at about
₹9,500 and ₹1,900, at Azure's own rate of about ₹95 to the dollar. Roshan said the most he can spend is
₹1,500 a month. So the ceiling moved to rupees, with the same shape as before:

| | Amount |
|---|---|
| Ceiling | ₹1,500 |
| Planned spend | under ₹750 |
| Alarms | ₹1,050 and ₹1,275 |
| Brake | ₹1,425 |
| Model budget | ₹1,000 |
| Router cap | $10 |

**What it changes later:**
- Phase 7 cannot run anything all month (an Arm VM is about ₹4,700), so hosting is on demand only.
- Phase 2 adds an automated brake that removes the deployment at the ₹1,425 alert, because alerts alone
  don't stop anything.

**Lesson:** a budget written in dollars was an assumption about the invoice. Read the billing currency
before writing an amount. An alarm above what the owner can pay is not an alarm.

## THL-24: the cost guardrails come before the deployment (ADR-0014)

**Ask:** Roshan: "can we control it like how we did in kaval project, like delete or pause resource
when not in use, add guardrails". He chose all of them, the brake included, built before the Claude
deployment. That moved ADR-0013's Phase 2 brake to Phase 0.

**Checked live (read-only) before designing:**
- A Claude Haiku 5.5 deployment's **capacity is its rate limit**: each unit is 1 request and 1,000
  tokens a minute, and the default is 10 units (the Azure model catalogue).
- Policy aliases exist for `deployments/sku.capacity`, `sku.name`, `model.name`, and for AI
  Search's `sku.name`.
- Prices: Haiku $0.10 / $0.50 per million tokens; Automation's first 500 minutes are free;
  secure webhooks are free at this volume.

**Built** (TDD, one commit per step): `guardrails.json` holds every number once. On top of it:
- three policy rules, with a small evaluator test;
- the brake runbook (standard library only) and its Terraform (`azurerm` 5.14);
- `make foundry-up` / `foundry-down`, and the read-only `make azure-sweep`;
- `tf.py`, which passes the subscription and the two names to Terraform without a shell;
- a test that the documents quote the numbers.

**Worst case, by design:** ₹82 a unit a day; at the cap of 3, ₹246 a day; three days of budget lag
come to ₹738, inside the ₹750 between the plan and the ceiling. At Azure's default of 10 units it
would have been about ₹820 a day.

**Defects caught before any Azure call:**
- A deployment created **without** a capacity would get Azure's default of 10 and pass a "greater
  than 3" rule. The rule now also refuses a missing capacity, and a mutation test proves the
  clause matters.
- Custom roles can't be assignable at one resource. The brake's role is defined on the group and
  assigned on the Foundry account only.
- Sourcing `.env` in the Makefile would have run every password as shell code. `tf.py` reads it as
  data instead.
- The commit hook refused the `test:` type, so the wiring commit is `feat:`.

**Blocked, correctly:** Claude Code's auto-mode check stopped Claude from editing
`.claude/settings.json`. The edit added the guardrail denies, and also allow rules for its own
commands. Claude wrote the change up as a proposal. Roshan read it and said to apply it, and it
went in as its own commit. All 257 tests pass.

**Next:** Roshan's go for each live step in Lab 00 §5: providers, plan, apply, the refused
capacity-4 deployment, the brake's dry run and its action-group test, `foundry-up`, the key, 7 PASS,
one paid `ping`, `foundry-down`, a clean sweep, and the meter check within 72 hours.

**Measured:** about 2 hours of one session. Pages reviewed by Roshan: the R14–R20 wording (one
screen). Tokens: not measured.

## THL-24 live: the guardrails proven, Claude answered, parked again

Every live step of Lab 00 §5 ran today, each on Roshan's go. The evidence is in the lab.

**Four things the live run found that no test had:**
1. **The cap rule could not be evaluated.** Azure answered `InvalidPolicyEvaluation`: the
   capacity reached the rule as text, not a number. A rule that can't be evaluated refuses
   everything, so even the approved deployment would have been blocked. Fixed in PR #8 by
   converting the capacity to a number first.
2. **Claude deployments need Anthropic's attestation.** The organization, country and industry go
   in `modelProviderData`. The Azure CLI can't send it, so `foundry-up` now sends the deployment
   with `az rest` (PR #9). Roshan read Anthropic's terms and entered the fields in `.env`. For a
   personal project the organization is the person, and Azure accepted it. The subscription
   eligibility problem a community post warned about did not happen on pay-as-you-go in India.
3. **A deletion runs in the background.** The brake's delete is accepted at once, and the
   deployment shows `Deleting` for about 30 seconds. During that time `foundry-up` said "UP
   already". Fixed on the evidence branch, test first.
4. **The brake's notice e-mail needs a verified address.** Azure holds action-group e-mail until
   the address is confirmed with a one-time code, which expires in 30 minutes. The code from the
   apply expired unclicked, so the test e-mail never came, while the API still said `Enabled`.
   Roshan re-saved the action group and verified, and the e-mail arrived. Lab 00 now verifies
   right after the apply.

**What is proven:**
- **The fence (R15):** a capacity-4 deployment is refused by policy.
- **The brake (R16):** fired the way a budget fires it, through the action group. It deleted the
  live deployment.
- **Park and unpark (R14):** `foundry-up` holds every guardrail, then creates the deployment.
- **The sandbox check (R13):** 7 PASS, with Claude answering a token count.
- **The sweep (R17):** clean after `foundry-down`.

**Cost:** one paid call, 10 input tokens and 1 output token, about $0.0000015. Everything else was
free. Whether the token counts are free on Foundry, and whether the charge lands under
`rg-thalam` (R20), shows in Cost analysis by 2026-11-25.

**Lesson worth keeping:** a guardrail you have not watched fire is a guess. Two of the four
findings would have stopped Phase 2 on its first morning, and a third would have let the brake
fire without telling anyone. Unit tests modelled Azure from its documentation, and none of the
four showed up in them.

**Drift left on purpose:** the portal re-save renamed the action group's e-mail receiver
(`owner` became `owner_-EmailAction-`). `make guardrails-plan` shows that one in-place change; the
next `guardrails-apply` sets the name back.

## THL-25: the dashboard, Kaval's for Thalam

Roshan asked for the same kind of artifact Kaval has: one page showing progress and everything
around it. Built the same way as Kaval's, as a generated mirror and not a hand-kept page, because a

- **`make dashboard`** runs `scripts/tracking/dashboard.py`, which reads ROADMAP.md, the specs,

  decides, who writes, and the guardrails around the model) and Decisions (ADRs, future scope).

- **Checks:** 8 new tests (279 in all), ruff and mypy clean. Ruff skips only the line-length rule

- **What the first build showed:** ROADMAP.md's Phase 0 list is behind. Five done items are still
